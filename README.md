# Multicam Replay для OBS Studio

Мгновенный повтор (instant replay) с нескольких камер для спортивных трансляций, по идее аналог Instant Replay в vMix.
До 4 камер, один источник повтора, переключение камер во время воспроизведения, замедление, шаг по кадрам.

Плагин состоит из двух частей:

| Компонент | Что делает |
|---|---|
| **Фильтр «Multicam Replay Capture»** | Вешается на каждую камеру. Пишет сырые кадры камеры в кольцевой буфер в ОЗУ. |
| **Источник «Multicam Replay»** | Хранит клипы и проигрывает выбранную камеру. Все хоткеи живут здесь. |

## Почему нагрузка на CPU и GPU минимальная

- **GPU не используется при записи.** Оригинальный obs-replay-source в режиме без async-фильтра читает кадры из видеокарты (`gs_stage_texture` + `map`), что вызывает синхронизацию GPU. Здесь кадры берутся из async-фильтра камеры, до рендера.
- **Нет конвертации и кодирования.** Кадр хранится в родном формате камеры (NV12, YUY2, I420 и т.д.). Это в 1.5-2.5 раза компактнее BGRA, и на кадр приходится один `memcpy`.
- **Нет аллокаций на кадр.** Блоки памяти берутся из пула и переиспользуются.
- **«Save replay» мгновенный.** Клип не копирует данные, а берёт кадры из буфера по ссылке (refcount).
- **При воспроизведении работает одна камера.** Один кадр отправляется в OBS только когда он реально меняется (при 50% скорости это каждый второй тик).

## Расход памяти

Кадр 1080p NV12 весит 3.1 МБ, YUY2 около 4.1 МБ.

| Режим | На камеру в секунду | 4 камеры, буфер 10 с |
|---|---|---|
| 1080p30 NV12 | 93 МБ | 3.7 ГБ |
| 1080p60 NV12 | 187 МБ | 7.5 ГБ |
| 720p60 NV12 | 83 МБ | 3.3 ГБ |

Сохранённые клипы делят кадры с буфером, но когда кадры «стареют» в буфере, клипы продолжают их удерживать. Поэтому полная оценка: буфер + (число клипов x длина клипа x 4 камеры). Для этого есть два лимита: «Лимит памяти для камеры» в фильтре и «Общий лимит памяти» в источнике (при превышении удаляются самые старые клипы).
Для 4x1080p30 разумно иметь 16 ГБ ОЗУ и более.

## Установка и настройка

1. Соберите плагин (раздел «Сборка») и скопируйте папку `obs-multicam-replay` из `release` в `%APPDATA%\obs-studio\plugins\`.
2. На **каждую камеру** (Video Capture Device, NDI, SRT, медиа-источник): ПКМ → Фильтры → в списке **Аудио/видеофильтры** (левый нижний «+») → **Multicam Replay Capture**. Фильтр асинхронный, поэтому в списке «Эффекты» его нет.
   Группа одинаковая у всех (например `main`), номер камеры у каждой свой: 1, 2, 3, 4.
3. Добавьте источник **Multicam Replay (повтор)** (Источники → «+») (в сцену повтора), в нём укажите ту же группу.
4. Настройте хоткеи в *Настройки → Горячие клавиши*, найдите строки с именем вашего источника.

### Окно управления

**Инструменты → Multicam Replay: окно управления** открывает отдельное окно. Свойства источника открывать не нужно. В окне:

- выбор источника повтора (если их несколько) и большая кнопка **СОХРАНИТЬ ПОВТОР**;
- кнопки камер 1-4 (активная камера подсвечена красным);
- пуск/пауза, кадр назад и вперёд, сначала, реверс, предыдущий / следующий / последний клип, скрыть, очистить;
- скорость: 25 / 50 / 100% и ползунок 5-400%;
- длина клипа и пост-ролл;
- переключатель «Поверх всех окон» и строка состояния (клип, камера, режим, позиция, занятая ОЗУ).

Окно можно держать на втором мониторе, оно работает независимо от хоткеев. Хоткеи ниже остаются доступными для Stream Deck и клавиатуры.

### Хоткеи

| Действие | Описание |
|---|---|
| Save replay | Сохранить клип: последние N секунд со всех камер (плюс пост-ролл, если задан). |
| Play / Pause, Restart | Пуск и пауза, воспроизвести клип сначала. |
| Camera 1-4 | Переключить камеру, позиция на таймлайне сохраняется. |
| Faster / Slower / 100% / 50% / 25% | Скорость воспроизведения. |
| Step frame forward / back | Покадровый шаг (ставит на паузу). |
| Reverse | Сменить направление. |
| Previous / Next / Last clip | Навигация по клипам. |
| Stop and hide, Clear | Скрыть источник, удалить все клипы. |

Хоткеи можно вызывать из Stream Deck, через obs-websocket (`TriggerHotkeyByName`, имена `mc_save`, `mc_cam1`, `mc_speed_50` и т.д.) или кнопками в свойствах источника.

### Типичная схема работы

1. Основная сцена: камеры в программе, у каждой стоит фильтр Capture.
2. Сцена «Replay»: источник Multicam Replay (+ плашка REPLAY).
3. Событие произошло → **Save replay** → переключаете сцену на Replay → при необходимости Camera N / 50% → по окончанию обратно на программу.
   Или включите в источнике «Начинать воспроизведение сразу после сохранения» и пост-ролл 2-3 секунды.

## Ограничения (v0.1)

- Работает только с **асинхронными** источниками: камеры, карты захвата, NDI, SRT, медиа. Захват окна, игры, браузер сюда не подходят (там кадры рождаются на GPU).
- Звук не записывается (в трансляциях со спортом повтор обычно идёт под программным звуком). Это сознательный выбор ради нагрузки.
- Нет интерполяции кадров: при 25% скорости каждый кадр повторяется. Для плавного слоумо нужны камеры 50/60 fps.
- Синхронизация камер идёт по времени прихода кадра в OBS (точность порядка периода кадра). Для генлок-съёмки с жёсткой синхронизацией по кадру нужна доработка.
- Нет экспорта клипов в файл.
- Максимум 4 камеры (константа `MC_MAX_CAMS` в `src/mc-common.h`; при увеличении нужно добавить хоткеи и кнопки).

## Сборка (Windows, готовый проект)

Проект уже собран на базе официального obs-plugintemplate: ничего заменять не нужно.

1. Установите [Visual Studio 2022 Community](https://visualstudio.microsoft.com/) с компонентом **Разработка классических приложений на C++** и [CMake](https://cmake.org/download/) (при установке выберите «Add CMake to PATH»).
2. Распакуйте проект в папку с коротким путём без кириллицы, например `C:\dev\obs-multicam-replay`.
3. Запустите **`build-windows.bat`** (двойной клик). Первый запуск скачает заголовки и библиотеки OBS (несколько сотен МБ).
4. Готовый плагин появится в папке `release\obs-multicam-replay`. Скопируйте эту папку целиком в `%APPDATA%\obs-studio\plugins\` (вставьте этот путь в адресную строку Проводника). Должно получиться `...\obs-studio\plugins\obs-multicam-replay\bin\64bit\obs-multicam-replay.dll`. Папку `plugins` создайте, если её нет. OBS должен быть закрыт. Папка `obs-plugins` в каталоге установки OBS для такой структуры **не подходит**: OBS её не читает.

Вручную те же шаги: `cmake --preset windows-x64`, `cmake --build --preset windows-x64 --config RelWithDebInfo`, `cmake --install build_x64 --config RelWithDebInfo --prefix release`.

Сборка под macOS и Linux идёт по стандартным пресетам шаблона (`macos`, `ubuntu-x86_64`), а GitHub Actions из `.github` соберёт все платформы автоматически при пуше в репозиторий.
